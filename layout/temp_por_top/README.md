# temp_por_top — block-level assembly (issue #240, T1 item 2)

`cell.json` places the four committed leaf streams (`bias_core`,
`por_comparator`, `por_output_chain`, `temp_core`) as `blocks[].cell` siblings,
stacked in y, and wires the nets `design/temp_por_top.sch` connects between
them in a left-hand channel, one metal plane per crossing net:

| Net | Plane (klt role) | Note |
| --- | --- | --- |
| VDD / VSS | met3 / met4 (`metal4`/`metal5`) | trunks at x=-150 / -200 |
| IBIAS | met5 (`metal6`) | only plane that clears `bias_core`'s own IBIAS pad |
| VREF | met1 (`metal2`) | `bias_core` does not promote VREF; port derived from its met3 label via `ports_from_labels` (leaf untouched) |
| BIAS_OK, POR_RAW | met2 (`metal3`) | |
| RESETn | met2 (`metal3`) | `por_output_chain` -> `temp_core` EN, on the leaves' own met2 stub pads (see below) |

VDD, VSS, RESETn, PTAT and CTAT are declared as top-level pins. No padring,
seal ring or other chip-level structure (out of scope).

Reproduce (klt `0.9.2`, commit `046ba74652fc`, `layout/pdk.json`'s
`klt_commit_pin`):

    python3 layout/bin/compose-cell.py layout/temp_por_top/cell.json --check

The rebuilt GDS is byte-identical to the committed one.

### The RESETn leg (re-routed, #453)

The post-#419 `por_output_chain` stream draws the native-Vt `massist` device
together with VDD/VSS met1 planes that enclose the leaf's `RESETn` li1 stub
pad, so no met1 escape from that stub exists any more — the pre-#453 route
(`metal2`, first waypoint at the old li1 port) fails composition with
`nets left unrouted by gen-compose: ['RESETn']` (the escape would short to
the VDD plane). The repaired leg declares the `por.RESETn` and `temp.EN`
ports on the **met2 (69/20) landing pads the leaves' own stubs already
draw** (at `172.46, 43.0` and `-8.5, 23.72` leaf-local) and routes the net
on `metal3` (met2), landing on those pads directly — no via, no met1 wire,
and no same-layer crossing of the `BIAS_OK`/`POR_RAW` met2 trunks (they end
at y=307.5/543.8; the RESETn trunk runs at y=620 and x=-400). The leaf
streams are untouched.

## Results (recorded, not all passing)

All artifacts below were produced by this re-render (#453) at one klt build:
`0.9.2`, commit `046ba74652fc`, KLayout `0.30.13` (`layout/pdk.json`'s pin).

- **DRC: clean, 0 violations.** (History: issue #243 regenerated the leaf
  streams under the then-pinned klt — they were generated by klt 0.6.0,
  before klayout-tools#2936 added the `poly.endcap.diff.1` rule/generator
  fix, and read 351 violations when re-checked — then re-assembled this top;
  this re-render at klt `0.9.2` stays clean.)
- **ERC (`erc.json`, `erc-supply-spec.json`, block-specific): `erc_status:
  clean`, 0 findings.** Two well-scoped `ties[]` entries: `nwell_vdd` (n-wells
  to `VDD`) and `nwell_nt` (the two `temp_core` wells of `XMI1`/`XMI2`, whose
  bulk is the signal net `NT` in the schematic, tied to `NT`). One n-tub layer
  carries both classes and no drawn layer separates them, so each entry is
  scoped by `well_requires_boxes` / `well_excludes_boxes` using the two well
  boxes `(71.84, 724.96, 79.07, 758.38)` and `(80.47, 724.96, 87.7, 758.38)`
  um, taken from the earlier `erc.missing_tie` findings. That membership is the
  caller's assertion, so both ties are named under
  `erc_coverage.checked_by_well_assertion`; neither was skipped as degenerate.
  The declaration is falsifiable: pointing `nwell_nt` at `VDD` in a scratch
  copy returns the two `erc.missing_tie` findings. VDD and VSS are each one
  island at the top. Run as `klt erc <gds> <spec> --deck sky130`: klt `0.9.2`
  needs the deck (or hand-asserted `ties[].isolation_boxes`) to decide
  substrate isolation for `erc.supply_short` — without it the check reports
  `substrate_isolation_undecidable` and signoff item 11 goes `unmet`. Antenna
  grading is still omitted (`status: not_checked`,
  `antenna_tables_omitted: false`), and **the p-substrate tie class is still
  not checked** (unexpressible, disclosed in the spec's `ties_disclosure`; see
  `layout/bias_core/erc-supply-spec.md`).
- **LVS: `match`, 154/154 devices, 71/71 nets — `XMASSIST` included, no
  exclusion.** The top is recomposed from the current leaf stream (PR #419),
  so the native-Vt `massist` device is drawn, extracted (drain `RESETn`, gate
  `VDD`, source/bulk `VSS`, `L=25 W=1` um) and compared against the
  reference's `XMASSIST ... sky130_fd_pr__nfet_05v0_nvt` card; the
  `lvs.drop_prefixes` entry is gone. Also disclosed by klt: `PNP` compared on
  `NE` only; resistor/MiM values not compared (reference `R=0`/`C=0`
  placeholders); `topology.flattened` (reference flattened). The compare is
  **flavour-blind**: the extracted netlist bins MOS generically (`nfet`, no
  per-flavour class), so the match proves the card's topology and `L`/`W`, not
  the native-Vt flavour binding itself. Turning `compare_mos_flavour` on needs
  the 28 5 V devices drawn with their `hvi` marker, which
  [klayout-tools#6025](https://github.com/2AMLogic/klayout-tools/issues/6025)
  blocked at this pin; the fix merged after the `0.9.2` release in
  [klayout-tools PR #6185](https://github.com/2AMLogic/klayout-tools/pull/6185)
  (commit `89b2cc61a9c4`), so a flavour-aware run needs a klt release
  containing that commit — a separate issue, with the leaf re-render it
  requires.
- LVS needs `extract.hierarchical_cells` + `lvs.flatten_layout`: flat
  extraction collapsed leaf-internal nets whose labels recur across leaves
  (`pb`/`PB`, `nz`/`NZ`, ...), giving a false 120/152 mismatch.

Items 3, 4 and 11 of the signoff manifest cite this block's `drc.json`,
`lvs.json` and `erc.json` (#259), and render as the signoff report states: 3,
4 and 11 `met`, item 4 with no exclusion.
